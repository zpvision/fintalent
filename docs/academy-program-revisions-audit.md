# Аудит версий программ Академии

Дата: 2026-11-08. Проверен локальный код; production не опрашивался.

## Статус работы

Новая публикация подключена к редактору, учебной комнате, потокам и аналитике.
Существующий ID версии сохраняется, меняется указатель опубликованной редакции.
Production, его PostgreSQL, S3 и сервисы не использовались; deployment и push
не выполнялись. Изменения остаются в локальном рабочем дереве.

Для проверок создан отдельный Docker PostgreSQL **18.6** на loopback-порту 55493,
база `fintalent_revisions_test`. Расширения сверх стандартного образа не нужны:
полная инициализация проекта проходит на нём. Реквизиты сгенерированы для теста,
не взяты из `.env` production и не записаны в репозиторий. Новые DB-тесты требуют
явный `ACADEMY_REVISIONS_TEST_DSN`, не подставляют `DATABASE_URL` и допускают
localhost только для этого имени базы и порта. Каждый тест создаёт собственную
проверенную схему и очищает только её.

### Карта зависимостей

```text
courses
  ├─ маркетинговая программа лендинга (независима)
  └─ academy_course_programs
       ├─ academy_modules → academy_lessons → academy_lesson_blocks (общий черновик)
       ├─ academy_media_assets / academy_asset_links
       └─ academy_program_versions (immutable JSON)
            ├─ academy_version_releases
            │    ├─ academy_cohorts → staff / schedule / events
            │    └─ academy_enrollments
            │         ├─ academy_lesson_progress / academy_learning_events
            │         ├─ academy_test_attempts
            │         └─ academy_assignment_submissions → reviews / files
            └─ academy_assessment_versions ← attempts / submissions
```

Версии используют общие неизменяемые медиа, а также исходные профессиональные
`test_versions` при подготовке проверок. Уже подготовленный Academy assessment
содержит отдельный снимок вопросов и решений. Изменение профессионального теста
не обновляет этот снимок. `freezeAssessments` пропускает уже имеющееся определение.

Если убрать урок из общего черновика, опубликованный JSON и история не меняются.
Если начать менять опубликованный JSON, старые записи progress сами не удалятся,
но `findLesson` перестанет находить урок, а исторические reviews используют JOIN
к текущему дереву. Поэтому сохранение строк само по себе недостаточно для
доступности истории.

### Конкурентность и кэширование

Общий редактор проверяет `academy_course_programs.revision` под блокировкой
родительской программы. `useAcademyDraft` объединяет серверные ID с локальными
правками и сохраняет резервный черновик в sessionStorage по пользователю и курсу,
без версии. Этот ключ необходимо расширить до версии до включения нового UI.

JSON API в основном отправляет `Cache-Control: no-store`. Учебная комната держит
полное дерево в React state; open/complete могут обновлять enrollment отдельно
от дерева. Токена согласованной опубликованной редакции сейчас нет. Аналитика
читает данные внутри repeatable-read транзакции, но это не решает согласованность
отдельных запросов учебной комнаты.

## Реализованная модель

### PostgreSQL — миграция 093

- `academy_program_versions.id` остаётся постоянным ID логической версии.
  Старая строка и её исходный JSON не изменяются и защищены прежним триггером.
- `academy_program_version_drafts` хранит самостоятельный JSON-черновик каждой
  версии, свой счётчик конфликтов, автора/дату и копии источников вопросов тестов.
- `academy_program_revisions` хранит append-only публикации: номер редакции,
  состояние программы, определения проверок, метаданные, автора/дату и ключ
  идемпотентного запроса.
- `academy_program_revision_heads` выбирает актуальную редакцию. Составной FK
  запрещает ссылку на редакцию другой версии.
- Старые опубликованные версии получают редакцию 1 с тем же содержимым и датой
  публикации. Старые потоки, зачисления, оценки и ключи прогресса не переписываются.
- `academy_assessment_versions.publication_revision_id` связывает новые
  определения с редакцией программы. У старых определений поле остаётся NULL.
  Прежняя уникальность «одно определение навсегда» заменена уникальностью внутри
  редакции; PK, составные FK результатов и immutable-триггеры сохраняются.
  FK новой редакции отложен до commit, чтобы публикация была одной транзакцией.
- `academy_current_program_versions`, `academy_current_version_releases` и
  `academy_current_assessment_versions` дают согласованный текущий срез.
- `academy_all_program_contents` защищает медиа, используемые оригиналами,
  черновиками и любой публикацией. `academy_editable_entities` разрешает загрузку
  в новые уроки JSON-черновика, ещё не существующие в старом реляционном дереве.
- `academy_lessons.access_mode` поддерживает старый редактор; JSON-уроки версии
  также имеют `schedule` / `immediate`. Значение по умолчанию — прежнее расписание.
- `academy_student_metrics` использует текущую редакцию и актуальные обязательные
  проверки. Округление процента приведено к целочисленному расчёту Go. Архивные
  задания не создают новые сигналы текущей просрочки.

Полная цепочка: `//go:embed` в `academy_module.go` → `Exec` последним шагом
`prepareAcademyDatabase` → существующий `prepareDatabase`. Повторное применение
не перезаписывает черновики и не сбрасывает указатель публикации на редакцию 1.

### Сохранение и публикация

1. Редактор загружает выбранную версию и её отдельный черновик. Общий старый
   реляционный черновик используется для первоначального создания/импорта и
   совместимости старых клиентов.
2. Автосохранение передаёт ID версии и её счётчик. Сервер проверяет владельца,
   принадлежность курсу, содержимое, медиа и тесты. Устаревший счётчик даёт 409.
3. Preview показывает подготовленную программу без зачисления и записи результатов.
4. Подтверждение публикации содержит реальные изменения, потоки, зачисления и
   число уникальных учеников. Изменения требований отделены от косметических.
5. Публикация блокирует область курса/черновика, проверяет готовность, замораживает
   определения и вставляет редакцию. Указатель переключается только в той же
   транзакции. Ошибка откатывает все связанные вставки.
6. Повтор того же счётчика/ключа возвращает существующую публикацию. Новая
   логическая версия при сохранении или исправлении не создаётся.

Создание независимой версии копирует только опубликованное состояние выбранного
источника. Его неопубликованный черновик не читается. Модули, уроки и блоки
получают новые логические ключи. Авторизованные ссылки на неизменяемые медиа
копируются транзакционно; сами файлы и S3-объекты не дублируются. Прогресс не
копируется. Номер версии резервируется под блокировкой; старые версии доступны
для дальнейшего редактирования.

### Тесты, задания и исторические результаты

Копии вопросов принадлежат черновику выбранной версии, а не общему изменяемому
профессиональному тесту. После изменения теста в разделе «Тесты» автор нажимает
**«Обновить связанные тесты»** в нужной версии и затем публикует изменения.
Другие версии не подхватывают эти правки даже при последующей косметической
публикации. Новая независимая версия первоначально получает именно опубликованные
вопросы источника, а не его более свежий профессиональный тест.

Для каждой публикации сохраняется отдельное определение проверки; используется
прежний `testmodule/domain.Grade`. Начатая попытка, исторический просмотр, ответ
и завершение находят определение через собственный assessment_id с проверкой
зачисления и логических ключей. Публикация и архивирование не меняют вопросы,
ответы, проходной балл и оценку такой попытки. Новые попытки используют новое
определение. Лимиты и ключи повторных запросов учитываются в рамках зачисления
и логического блока, а не обнуляются каждой публикацией.

У работ сохраняются исходные условия, файлы, критерии, оценки и история решений.
Проверка преподавателем открывает определение конкретной submission. Для
исторических условий и их материалов есть защищённое чтение; оно не открывает
произвольные файлы программы. Архивная работа остаётся в очереди/истории проверок.
Нельзя переиспользовать ключ исторического блока для другого типа проверки.

`assessmentOutcomes` объединяет действительные достижения разных редакций одного
логического блока. Историческая успешная оценка не пересчитывается по новым
вопросам. Новая обязательная проверка с новым ключом остаётся невыполненной.

### Учебная комната, прогресс и согласованность

Все читатели выбирают текущую редакцию **версии зачисления**, а не последнюю
версию курса: учебная комната, потоки, самостоятельный доступ, приглашения после
оплаты, CRM, отчёты, аналитика и административная диагностика.

Программа и метаданные читаются одним SQL-срезом. Ответ содержит
`publication_revision_id`. Запрос нового действия со старым токеном получает
409 и предлагает обновить программу. Историческая активная попытка сохраняет
свою редакцию. Транзакции записи прогресса берут shared lock указателя, поэтому
публикация не меняет требования посреди завершения урока/попытки.

Клиент опрашивает прогресс раз в 30 секунд и сообщает о новой публикации.
**«Обновить программу»** сначала сохраняет ответы, затем заменяет дерево целиком.
Начатая работа не прерывается принудительно. Новая страница сразу загружает
актуальную программу. Отдельные поздние ответы не подменяют дерево другой редакцией.

`enrollmentSummary` используется в учебной комнате и аналитике учеников.
Добавление обязательного материала может уменьшить текущий процент незавершившего
курс, но сохранённые статусы уроков и даты не удаляются. Достигнутое завершение
и первоначальный completed_at сохраняются после публикаций. Дополнительные
материалы доступны при действующем доступе; необязательные не входят в знаменатель.
Текущий процент материалов и исторический статус завершения — разные понятия.

Отдельная уже существовавшая **аудируемая административная корректировка оценки**
сохраняет возможность контролируемого пересчёта ошибочного результата. Обычная
публикация/обновление прогресса не получает эту внутреннюю capability.

Сертификаты Академии в исходном проекте не выдаются: соответствующих сущностей и
выдачи нет, что явно указано в прежней учебной комнате. Сертификаты резюме и другие
модули не изменялись. Реальную выдачу/отзыв сертификата проверить здесь нельзя.

### Доступность и медиа

По умолчанию продолжают действовать правила потока, IANA timezone, статус запуска,
срок доступа и блокировки. Новый урок без индивидуального правила наследует
правило модуля либо старт потока. **«Доступен сразу»** обходит календарное правило
только в уже запущенном/завершённом потоке и не обходит приостановку зачисления,
истечение доступа или блокировку пользователя. Старые расписания не переписываются.

Файлы проверяются через существующие сервисы. В ученическом маршруте файл должен
принадлежать текущему уроку его версии либо исходным условиям принадлежащей ему
работы. Подстановка ключа другой версии не предоставляет доступ. Удаление
используемого историей/черновиком файла запрещено; физического переноса S3 нет.

### Frontend

Используются прежние AcademyPage, дерево, Editor.js, настройки, диалог и renderer.
Новый `ProgramVersions` предоставляет выбор любой версии, дату публикации,
состояние изменений, counts, независимое копирование, preview и историю.
Семантика «зафиксировать навсегда» удалена из актуального интерфейса. Страница
«Ученики» направляет в этот редактор, сохраняя управление зачислениями.

Ключ sessionStorage включает версию. При переключении сначала выполняется flush,
на время операции редактор блокируется, ошибки/конфликты видны и в диалоге.
Старый общий несохранённый черновик не присваивается случайной версии: его можно
скачать отдельно. Исходный механизм восстановления и экспорта правок сохранён.

В настройках урока есть обязательность, режим открытия и архивирование/восстановление
через существующие статусы. Архивирование сохраняет урок в редакторе как черновик,
снимает обязательность и влияет на учеников только после публикации. После
восстановления автор проверяет обязательность. Историю публикаций можно открыть
в защищённом предпросмотре.

## API

Префикс владельца: `/api/academy/courses/{course}/versions`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/versions` | Логические версии, публикации, изменения и реальные counts |
| POST | `/versions` | Независимая версия из `source_version_id`; 0 только для первоначальной программы без публикаций |
| GET / PUT | `/versions/{version}/draft` | Чтение/сохранение отдельного черновика |
| POST | `/versions/{version}/actions` | Прежние структурные команды выбранной версии |
| GET | `/versions/{version}/publication` | Изменения, готовность и затронутая аудитория |
| POST | `/versions/{version}/publish` | revision, acknowledge_warnings, request_key |
| POST | `/versions/{version}/refresh-tests` | Явно обновить копии вопросов только этой версии |
| GET | `/versions/{version}/preview` | Preview черновика; `?revision=id` — исторической публикации |
| GET | `/versions/{version}/history` | История публикаций |
| GET | `/versions/{version}/history/{revision}` | Полный исторический снимок для авторизованного аудита |

Совместимость: старые `/program` и `/actions` принимают version_id и применяют
тот же сервис; без него продолжают работать с первоначальным деревом.
Старый POST `/versions` с `{revision}` сохраняет snapshot-контракт для legacy
клиентов. `/releases` использует новый сервис публикации. Ученические URL и
существующие ID зачислений не меняются. Новый необязательный query-параметр

## Как пользоваться

1. Открыть **Академия → Программа** и выбрать, например, **Версия 1**.
2. Изменить уроки/блоки: автосохранение сохраняет только её черновик.
3. Для бонуса снять **«Обязательный для завершения курса»**; при необходимости
   выбрать **«Доступен сразу»**.
4. Для нового теста добавить обычный блок и выбрать тест автора. Если изменены
   вопросы существующего профессионального теста, нажать **«Обновить связанные тесты»**.
5. Открыть **«Предпросмотр изменений»**, затем **«Опубликовать изменения»**.
   Проверить изменения и аудиторию, подтвердить публикацию.
6. Для версии 2 нажать **«Создать новую версию»**, выбрать опубликованную версию 1.
   Редактор переключится на независимый черновик.
7. Через список версий снова открыть версию 1: она по-прежнему редактируема.

## Развёртывание и ограничения

- Нужна резервная копия перед будущим развёртыванием. Production в этой работе
  не является тестовой средой; разрешение на deployment/push отсутствует.
- Обновить backend и frontend вместе. Миграция 093 запускается штатным prepare.
  Не применять её параллельно со старым обслуживающим binary: прежний writer
  определений не понимает новую уникальность и опубликованные редакции.
- Не удалять новые таблицы и не откатывать схему автоматически после появления
  новых публикаций. Старый binary читает только исходные snapshots, поэтому
  обычная замена binary на старый после новых публикаций не является полноценным
  откатом функциональности. Использовать совместимый фикс вперёд/контролируемый план.
- Большие файлы не копируются; S3-конфигурация и originals не меняются.
- Расчёт затронутой аудитории показывает зачисления отдельно от уникальных
  учеников. Исторические результаты остаются отдельными записями/публикациями.
- Копирование старой программы с неподготовленными определениями тестов требует
  сначала подготовить и опубликовать их в исходной версии; вопросы не выдумываются
  и не заменяются молча современным состоянием профессионального теста.
- Курс блокируется на время записи/публикации; разные черновики независимы, но
  операции одного курса сериализуются. На очень большой истории публикаций
  измерять стоимость проверки ключей и JSON-проекций перед дополнительной оптимизацией.

Пример безопасного запуска (пароль тестовый, задаётся в процессе, не в Git):

```powershell
$env:POSTGRES_PASSWORD = [guid]::NewGuid().ToString('N')
docker run -d --name fintalent-academy-revisions-test -p 127.0.0.1:55493:5432 --env POSTGRES_PASSWORD --env POSTGRES_DB=fintalent_revisions_test postgres:18
$env:DATABASE_URL = "postgres://postgres:$($env:POSTGRES_PASSWORD)@127.0.0.1:55493/fintalent_revisions_test?sslmode=disable"
$env:ACADEMY_REVISIONS_TEST_DSN = $env:DATABASE_URL
$env:RUN_COURSES_DB_TESTS = '1'
$env:RUN_S3_LIVE_TESTS = '0'
go test ./...
npm run build
$env:RUN_ACADEMY_REVISIONS_BROWSER = '1'
go test . -run TestAcademyProgramRevisionBrowser -v -timeout 4m
```

Команда Docker откажется перезаписывать одноимённый контейнер. Не заменять пароль
существующего экземпляра случайным новым: использовать его известные тестовые
реквизиты или отдельный новый стенд. Не запускать `main` с production `.env` для
этих проверок.

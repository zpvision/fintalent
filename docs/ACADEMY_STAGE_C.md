# FinTalent Academy — тесты и практические работы

Продолжение [Этапа A](ACADEMY_STAGE_A.md) и [Этапа B](ACADEMY_STAGE_B.md).
Общие пользователи, сессии, курсы, закрытые файлы, уроки и renderer сохранены.
Лендинг, профессиональный рейтинг и маркетинговая программа не изменяются.

## Работа автора

1. Открыть **Мои курсы → Академия → Программа и уроки**.
2. В блоке теста выбрать свою версию из существующего раздела **Тесты**.
   Вопросы создаются прежним редактором тестов. Для учебного контекста настроить
   обязательность, проходной процент, число попыток, время, пересдачу, лучший
   либо последний результат, показ правильных ответов и объяснений.
3. В задании заполнить инструкции и материалы; выбрать один или несколько
   форматов ответа. Каждый выбранный формат обязателен. Настроить максимальный
   и необязательный проходной баллы, число попыток, доработку и способ проверки.
   Критерии имеют стабильные ключи и порядок; сумма должна совпадать с максимумом.
4. **Зафиксировать версию**, опубликовать её в **Учениках**, выдать доступ.
5. Открыть **Задания и проверки**:
   `/profile/courses/{course_id}/academy/reviews`.
   В очереди доступны фильтры курса, модуля, урока, ученика, статуса и порядок
   отправки. Фильтры модулей/уроков учитывают назначенные исторические версии.
6. **Проверить** открывает большую панель с заданием, отправленным ответом,
   закрытыми файлами, критериями и историей. Можно взять работу на проверку,
   принять, вернуть на доработку или отклонить. Отказ/доработка требуют комментария.
   Баллы критериев суммирует сервер; принятие ниже проходного балла запрещено.
   Возврат на доработку разрешён, только если осталась следующая попытка отправки.
7. По умолчанию после решения открывается следующая работа в той же панели.
   Решения сохраняются с автором, временем, источником и ключом идемпотентности.

Тестовые попытки видны в отдельной вкладке очереди. Показатели рассчитаны по
реальным данным: текущие работы на проверке/доработке/принятые, число проверок,
средний процент завершённых тестовых попыток и доля принятых заданий среди
последних отправок. Черновики и просрочки без расписания не выдаются за статистику.
Карточка ученика дополнена результатами тестов и состояниями работ.

## Работа ученика

**Моё обучение → Продолжить обучение**. В блоке теста до начала видны количество
вопросов, порог, оставшиеся попытки и время. Вопросы выдаются после начала.
Ответы сохраняются последовательно с проверкой ревизии; доступны навигация назад,
вперёд, номера вопросов, таймер, повтор сохранения и история попыток.
Смена урока ожидает сохранения ответов. Неуспешное сохранение сохраняет введённое
в форме; предупреждение о закрытии защищает несохранённые изменения.

У задания доступны серверный черновик, текст, HTTPS-ссылки и файлы либо их
комбинация. Перед отправкой нужно заполнить каждый выбранный формат. После
отправки содержимое не изменяется. Доработка создаёт новую попытку, сохраняя
предыдущую; текст/ссылки копируются, файлы нужно прикрепить заново.
Ученик видит комментарий, оценку, баллы критериев и всю свою историю.
Ожидающие проверки работы обновляются при возврате во вкладку и каждые 20 секунд.

## Общий движок тестов и границы контекстов

`internal/testmodule/domain/grading.go` — общая функция `Grade`, выделенная из
прежнего профессионального `Service.Finish` без изменения формулы. Переиспользованы
`Question`, `Answer`, `AttemptAnswer`, четыре типа вопросов, скрытие решений и
стабильное перемешивание `PrepareAnswerOrder`. Для разбора результата используется
существующий React `Review` из `TestTakePage`. Создание тестов остаётся прежним.

Учебные попытки имеют собственное хранение, связанное с зачислением и снимком,
и не пишут в профессиональные `test_attempts`, статистику или резюме. Все баллы
считает сервер по закрытому снимку. Ограничения учебного теста задаются блоком,
независимо от ограничений профессионального прохождения исходного теста.

## Неизменяемость и совместимость

Новая миграция **`080_academy_assessments.sql`** подключена по цепочке embed →
`prepareAcademyDatabase()` → `prepareDatabase()` после 078/079 и повторяема.

- `academy_assessment_versions`: тип, урок/блок/версия программы, полная конфигурация
  блока и полный закрытый снимок вопросов с правильными ответами и объяснениями.
  Захват каждого теста — один согласованный MVCC-запрос, фиксация всего набора
  выполняется в транзакции со снимком программы. UPDATE/DELETE запрещены.
- `academy_test_attempts`: зачисление, версия проверки, номер, ключ запроса,
  ответы, ревизия, начало/deadline/окончание, серверная оценка и разбор. Результат
  завершённой попытки защищён триггером от изменения/удаления.
- `academy_assignment_submissions`: отдельная попытка, серверный черновик,
  текст/ссылки/ID файлов, ревизия, отправка, статус, назначение проверяющего и итог.
  Отправленное содержимое неизменяемо; окончательные решения не перезаписываются.
- `academy_submission_reviews`: append-only аудит назначения/проверок, критерии,
  баллы, комментарий, reviewer, время и источник `manual/automatic/ai`.
  Сейчас доступны только manual и честное автоматическое принятие формата.
- `academy_media_assets.submission_id`: связь ответа с существующим закрытым
  хранилищем. Нового файлового сервиса или таблицы пользователей нет.
- События используют `academy_learning_events`, уведомления — существующую
  таблицу `notifications`, без нового механизма рассылок.

Снимок содержит задания, критерии, пороги и лимиты. Изменение исходного теста,
черновика или новая публикация не меняют старые попытки и правила.

**Версии, созданные до Этапа C:** ранее вопросы тестов не фиксировались полностью.
Автор может явно нажать **Подготовить проверки этой версии** в разделе «Ученики».
Операция однократно фиксирует текущее содержимое исходных тестов; существующие
снимки проверок не заменяются. До подготовки ученик получает понятное сообщение,
а обязательная проверка не засчитывается. Восстановить историческое содержимое
изменённого до этого теста невозможно; такие вопросы следует проверить автору.

## Доступ, время и прогресс

Каждый ученический запрос проверяет пользователя, собственное зачисление, срок,
статус, принадлежность урока/блока его версии и файла его попытке. Проверки,
отправки и изменения доступа сериализуются блокировкой зачисления. Ревизии
защищают быстрые/параллельные записи; старые ответы API не заменяют новые в UI.

Правильные ответы и объяснения не выдаются во время попытки. После завершения
выдача следует раздельным настройкам автора. Question settings не передаются
ученику. Лимит попыток и deadline контролирует сервер, при повторном запросе
истёкшая попытка завершается по уже сохранённым ответам. Изменение часов браузера,
перезагрузка и повтор запроса не перезапускают таймер и не создают лишнюю попытку.

Владение курсом проверяется на backend для очереди, карточки, решения и файла.
Автор не может вручную проверить собственную работу. Черновики новых ответов
не раскрываются преподавателю через историю ранее отправленных попыток.
Файлы до **20 МБ**, MIME/содержимое и имена проверяются общими функциями Академии.
В публичную статику они не попадают; права включают конкретное зачисление/попытку.

Обязательные блоки теста и задания должны быть выполнены **все**. Отправка на
проверку не завершает задание. Принятие/успешный тест пересчитывают урок и курс
сервером. Необязательные блоки не мешают завершению, если правило урока отдельно
не требует соответствующий тип. `materials` без видео по-прежнему требует
подтверждения ученика; автоматического доказательства просмотра видео нет.
Лучший результат использует лучшую завершённую попытку; режим последнего
результата может вернуть урок в процесс после неудачной пересдачи. История
попыток при этом не изменяется, изменение требований записывается событием.

Автоматическое принятие задания проверяет **только наличие требуемых форматов**.
При нём запрещены критерии и проходной балл, оценка остаётся NULL. Качество
работы не объявляется проверенным. AI-оценок и LLM-вызовов нет.

## API

Ученический префикс:
`/api/academy/enrollments/{id}/lessons/{lesson_key}/assessments/{block_key}`.

| Метод / суффикс | Действие |
| --- | --- |
| GET `/` | Настройки, собственная история, текущая попытка; `?attempt=id` для разбора |
| POST `/start` | Учебная попытка `{request_key}` либо продолжение начатой |
| PUT `/attempts/{id}/answer` | `{revision,question_id,selected_answer_ids,text_answer}` |
| POST `/attempts/{id}/finish` | Серверный итог, идемпотентно |
| POST `/draft` | Черновик задания `{request_key}` |
| PUT `/submissions/{id}` | `{revision,answer:{text,links,asset_ids}}` |
| POST `/submissions/{id}/submit` | `{revision}`, неизменяемая отправка |
| POST `/submissions/{id}/files` | Multipart `file`, только в свой черновик |
| GET/HEAD `/submissions/{id}/files/{asset_id}` | Закрытый файл своего ответа |

Авторский префикс `/api/academy/courses/{course_id}`:

| Метод / суффикс | Действие |
| --- | --- |
| GET `/reviews` | Текущие отправки, показатели, фильтры status/module/lesson/student/sort/offset; до 100 строк |
| GET `/reviews/{id}` | Работа, задание, критерии, файлы, история отправок/проверок |
| POST `/reviews/{id}` | `{revision,status,score,criterion_scores,comment,request_key}`; возвращает next_id |
| GET/HEAD `/reviews/{id}/files/{asset_id}` | Авторизованное скачивание ответа |
| GET `/assessment-results?before=id` | Завершённые учебные тесты, до 200 строк |
| POST `/releases/{version_id}/assessments` | Явная подготовка проверок старой версии |

`GET/PUT /api/academy/notifications` — свои события обучения / `{ids}` для прочтения.
Публикация, комната и карточка ученика расширены без удаления API Этапов A/B.
Обновление прогресса выполняется внутри операций, отдельной доверенной клиентской
команды «увеличить процент» нет.

## Проверки и эксплуатация

- `go test ./...`; `go vet ./internal/academy ./internal/testmodule/domain ./internal/testmodule/service`.
- `npm run build`.
- Облачная PostgreSQL из локального DATABASE_URL в собственной временной схеме:
  `RUN_COURSES_DB_TESTS=1 go test . -run '^TestCoursesIsolatedPostgres$' -count=1 -timeout=15m`.
  Включает A/B/C: версии, таймер, секреты, попытки, доработку, критерии, доступ,
  приватные файлы, уведомления, self-review, автоматическую проверку формата и прогресс.
- `node scripts/academy-assessments-browser-check.cjs`: реальный React build,
  headless Edge, изолированные API fixtures, без DB/production/учётных данных.
  Тест → черновик → файл → отправка → доработка → новая попытка → принятие,
  переход к следующей работе, ошибки сети и размеры 360/900/1440.
- Регрессия: `scripts/academy-browser-check.cjs` и
  `scripts/academy-learning-browser-check.cjs`, включая ПрофиМаркет.

Пересобрать frontend и Go, перезапустить сервер. Миграции применяются автоматически.
Production Nginx, постоянный закрытый volume `ACADEMY_STORAGE_DIR` и backup необходимо
проверять при развёртывании. Лимит файлов 20 МБ не увеличивался.

Потоки и календарные дедлайны, команда кураторов, внешние рассылки и ИИ не включены.
Подготовлены привязка к зачислению/версии, nullable cohort, reviewer/назначение,
append-only решения и структурированные ответы/критерии. Будущая AI-проверка может
сохранить предложение как источник ai в состоянии проверки, затем получить
отдельное ручное решение преподавателя без перезаписи истории.

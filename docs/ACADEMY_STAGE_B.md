# FinTalent Academy — самостоятельное обучение

Документ фиксирует Этап B. Прохождение тестов, сдача и проверка работ добавлены
в [Этапе C](ACADEMY_STAGE_C.md); актуальные правила проверок описаны там.

Продолжение [редактора Этапа A](ACADEMY_STAGE_A.md). Лендинг и его программа
не меняются. Используются прежние пользователи, сессии, редактор, renderer и
закрытое файловое хранилище. Учебных аккаунтов, оплат и фиктивных потоков нет.

## Как начать

1. Автор: **Профиль → Мои курсы → Открыть Академию**. Подготовить материалы,
   опубликовать нужные модули и уроки, нажать **Зафиксировать версию**.
2. Открыть вкладку **Ученики**, выбрать подготовленную версию и опубликовать её.
   Проверка готовности показывает блокирующие проблемы и предупреждения.
3. Найти существующий аккаунт: точный email либо имя опубликованного публичного
   профиля (от трёх символов, до восьми результатов). Email в ответ не выдаётся,
   аккаунты автоматически не создаются. Выбрать версию и необязательный срок.
4. Ученик: **Профиль → Моё обучение** (`/profile/learning`) → **Начать обучение**.
   Комната: `/profile/learning/{enrollment_id}`. Программа на телефоне — drawer.
5. Автор видит прогресс, последнюю активность, пройденные уроки и историю доступа.
   **Управлять доступом** позволяет приостановить, восстановить, отозвать доступ
   или изменить срок, сохраняя прогресс.

Авторская комната-предпросмотр:
`/profile/courses/{course_id}/academy/room/{version_id}`. Не создаёт зачисления,
прогресса или событий. Просматривает подготовленную либо опубликованную версию;
предпросмотр черновика в редакторе сохранён.

## Версии и данные

Миграция `079_academy_learning.sql` идемпотентна и подключена после `078` через
`academy_module.go` → `prepareAcademyDatabase()` → `prepareDatabase()`.

- `academy_version_releases`: публикация полного append-only снимка Этапа A.
  Хранит также названия/описания привязанных версий тестов. UPDATE/DELETE
  запрещены триггером. Публикация одной версии идемпотентна.
- `academy_enrollments`: курс, существующий пользователь, опубликованная версия,
  автор/источник/дата зачисления, срок, право доступа, начало/завершение, последняя
  активность и урок. Составной FK не позволяет назначить версию другого курса.
  Nullable `cohort_id` зарезервирован для будущего настоящего потока; сейчас NULL.
- `academy_lesson_progress`: конкретное зачисление + версия + стабильный key
  урока; начало, последнее открытие, завершение, подтверждение изучения материалов.
- `academy_learning_events`: зачисление, начало обучения, открытие/повторное
  открытие урока, переходы, завершение урока/курса, изменения доступа. Ключ события
  защищает повторы. Избыточной телеметрии нет.

Право доступа (`active/suspended/revoked`, вычисляемое `expired`) хранится отдельно
от состояния обучения (`not_started/in_progress/completed`). Истечение проверяется
сервером при запросе, фоновый job не требуется. Завершение не отзывает доступ.

Зачисление фиксирует версию навсегда: новая редакция или публикация не подменяет
материалы старого ученика. Повторная выдача той же самостоятельной версии возвращает
существующее действующее/приостановленное зачисление. Новый поток в будущем сможет
иметь отдельное зачисление; новая версия уже сейчас может назначаться отдельно.

## Завершение и прогресс

- Процент рассчитывается сервером по обязательным опубликованным урокам
  опубликованных модулей. Необязательные уроки не меняют знаменатель.
- Нет обязательных уроков — 0%, без искусственного завершения курса.
- Обычный урок с правилом `manual` завершается явной кнопкой после открытия.
- `materials` без видео требует явного подтверждения ученика. Это аттестация
  самим учеником, не автоматическое доказательство просмотра.
- `materials` с видео пока не завершается: открытие не доказывает просмотр.
- Тесты и задания отображаются со структурированными инструкциями и материалами,
  но пройти/сдать их пока нельзя. Уроки с такими блоками либо правилами не
  завершаются. Обязательные требования остаются в знаменателе и не дают ложные 100%.
- Автор видит предупреждения о неподдерживаемых требованиях и должен явно
  подтвердить их перед публикацией. Обязательный черновой урок, пустые необходимые
  материалы или недоступность самостоятельного урока блокируют публикацию.
- Записи прогресса и события сериализуются блокировкой зачисления. Повторное
  завершение не дублирует результат. Последний урок сохраняется сервером; при входе
  выбирается он либо следующий незавершённый. URL также сохраняет выбранный урок.

## Права и файлы

Авторские API сохраняют gate курсов и ownership Этапа A. Ученические API проверяют
сессию, активного пользователя, собственное зачисление, статус/срок, опубликованный
урок конкретного снимка и принадлежность файла именно этому уроку. Нельзя получить
черновик или файл по одному ID. Служебные и заблокированные аккаунты исключаются.
При закрытом доступе комната возвращает метаданные зачисления, без программы/блоков.

Beta gate каталога/авторского редактора не блокирует выданное обучение. Меню
«Моё обучение» появляется у допущенных к курсам пользователей либо при наличии
зачисления; «Мои курсы» остаётся авторским разделом. Каталог сохраняет прежние права.
Один аккаунт может быть одновременно автором и учеником.

`LessonRenderer` общий для редактора и комнаты. В комнате URL каждого файла
содержит зачисление и key урока; сервер проверяет их, затем использует прежнюю
закрытую выдачу. Ограничение **20 МБ** не изменено, внешние видео — прежние источники.
Nginx и постоянный production volume/backup `ACADEMY_STORAGE_DIR` необходимо
проверить при развёртывании; конфигурации production proxy в репозитории нет.

## API

Авторский префикс: `/api/academy/courses/{course_id}`; прежние API Этапа A сохранены.

| Метод и путь | Назначение |
| --- | --- |
| GET `/releases` | Снимки, публикация, проверка готовности |
| POST `/releases` | `{version_id,acknowledge_warnings}` — публикация |
| GET `/releases/{version_id}/preview` | Комната автора без зачисления |
| GET `/user-search?q=...` | Ограниченный поиск зарегистрированных пользователей |
| GET `/students` | Ученики, серверный прогресс и доступ |
| POST `/students` | `{user_id,version_id,expires_at?,request_key}` — выдать доступ |
| GET `/students/{enrollment_id}` | Прогресс, уроки, история доступа |
| PUT `/students/{enrollment_id}` | `{status,set_expiration,expires_at?}` |

Ученик:

| Метод и путь | Назначение |
| --- | --- |
| GET `/api/academy/learning/access` | Наличие зачислений для меню |
| GET `/api/academy/learning` | Собственное обучение |
| GET `/api/academy/enrollments/{id}` | Программа назначенной версии, прогресс, resume |
| GET `/api/academy/enrollments/{id}/progress` | Серверный прогресс зачисления |
| GET `/api/academy/enrollments/{id}/lessons/{key}` | Урок и следующий урок |
| POST `/api/academy/enrollments/{id}/lessons/{key}/open` | `{event_key}` — открытие |
| POST `/api/academy/enrollments/{id}/lessons/{key}/complete` | `{materials_acknowledged}` |
| GET/HEAD `/api/academy/enrollments/{id}/assets/{asset_id}?lesson={key}` | Закрытый файл |

Коллекции используют курсор `?before={id}` и страницы до 200 зачислений со стабильным
порядком по ID. Frontend загружает страницы, затем применяет фильтры и сортировку;
изменение активности во время загрузки не сдвигает границы страниц.

## Проверки

- `go test ./...`; `go vet ./internal/academy`.
- Облачная PostgreSQL в собственной временной схеме:
  `RUN_COURSES_DB_TESTS=1 go test . -run '^TestCoursesIsolatedPostgres$' -count=1 -timeout=12m`.
  Требует локальный `DATABASE_URL`, не изменяет данные приложения. Проверяет также
  повторное применение миграций, версии, IDOR, файлы, сроки, idempotency и прогресс.
- `npm run build`.
- `node scripts/academy-learning-browser-check.cjs` — реальный React build,
  headless Edge и изолированные API fixtures, без DB/production/паролей.
  Публикация → зачисление → комната → завершение, ошибки сохранения, ограничения,
  все состояния доступа и размеры 360/900/1440. Скриншоты — в OS temp.
- `node scripts/academy-browser-check.cjs` — регрессия редактора Этапа A.

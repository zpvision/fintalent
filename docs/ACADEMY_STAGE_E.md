# FinTalent Academy — Этап E

Центр коммуникаций встроен в существующий кабинет Академии. Пользователи, авторизация, учебные версии, CRM, notifications и SMTP остаются общими с FinTalent. Лендинг курса и ПрофиМаркет не меняют бизнес-правил.

## Как пользоваться

1. Профиль → Мои курсы → Открыть Академию → **Рассылки**.
2. Создать рассылку: выбрать учеников/потоки/сегмент, подготовить письмо, выбрать время, проверить сводку и явно подтвердить запуск.
3. **Шаблоны**: восемь готовых писем, предпросмотр, редактируемые копии и собственные шаблоны. Редактор поддерживает восемь типов блоков, rich text через прежний AcademyRichEditor, сортировку мышью и кнопками, копирование, выравнивание, цвета кнопок, загрузку публичных изображений и мобильный предпросмотр.
4. **История отправок**: индивидуальные статусы, попытки, время, диагностический код и ручной повтор. После запуска содержимое рассылки фиксируется; изменения делаются в копии. Отмена затрагивает только ещё не начавшиеся отправки.
5. **Автоматизации**: событие → сегмент AND/OR → до восьми действий. Получатель действия — ученик, назначенный куратор или владелец курса. Новые сценарии создаются черновиками; активация требует подтверждения. Активный сценарий сначала приостанавливается для изменения конфигурации.
6. Уведомления ученика: `/profile/academy/notifications`; ссылка доступна из учебных уведомлений. Реклама выключена по умолчанию. Согласие подтверждает сам получатель. Отписка по непрогнозируемой ссылке: GET показывает подтверждение, POST отключает email этого курса.
7. В потоке → Кураторы владелец отдельно выдаёт **«Разрешить рассылки своим ученикам»**. Право проверки заданий не даёт права рассылки. Куратор ограничен назначенными зачислениями, преподаватель — своими потоками. Сотрудники не получают доступ к авторскому редактору.

## Данные и интеграция

Идемпотентная `082_academy_communications.sql` подключена полной цепочкой embed → prepareAcademyDatabase → prepareDatabase после 081. Сохраняет прежние программы, версии, зачисления и результаты.

Новые таблицы:

- `academy_email_templates` — собственные шаблоны, ревизии, мягкое удаление.
- `academy_campaigns` — письмо, аудитория, канал, категория, расписание, состояние, request_key и ревизия.
- `academy_automations` — триггер, конфигурация, состояние, поколение и начало наблюдения.
- `academy_automation_runs` — источник события, зачисление, условия, причина пропуска; уникальность сценарий/поколение/зачисление/событие.
- `academy_message_deliveries` — постоянная очередь и история сообщений, lease, статус, число попыток, стабильный Message-ID, неопределённость SMTP.
- `academy_delivery_attempts` — журнал отдельных попыток транспорта.
- `academy_communication_preferences` — настройки по пользователю и курсу, явное согласие на рекламу, случайный unsubscribe token.
- `academy_communication_audit` — создание, изменение, запуск, отмена, повтор, изменение подписки.

`academy_cohort_staff.can_communicate` дополняет существующую модель прав. SQL `academy_can_communicate` использует прежнюю область доступа к зачислению. View `academy_communication_events` нормализует **существующие** learning/cohort events; второй журнал обучения не создаётся.

Письмо хранится как структурированные блоки. Backend формирует email-совместимые таблицы с inline CSS; React-разметка не отправляется. HTML из rich text очищается существующей политикой; персонализация экранируется. URL проходят whitelist схем, изображения ограничены публичным хранилищем FinTalent. Изображения загружаются прежним `/api/profimarket/upload` (до 7 МБ), а не в закрытое хранилище уроков. В in-app notification помещается текст написанного сообщения и ссылка на существующий учебный кабинет/CRM.

Сегментация: белый список полей и операторов, параметры SQL, AND/OR, не более 30 условий, 100 потоков и 1000 явно выбранных зачислений. Прогресс, активность, результаты, незавершённые задания, доработка, работы на проверке, метки, куратор и статусы вычисляются из действительных данных. Предпросмотр показывает первые 100 имён без email. Одна рассылка адресуется уникальным пользователям; несколько зачислений одного человека не дублируют письмо. Максимальная аудитория одной рассылки — 10 000 получателей.

## API

Авторский namespace: `/api/academy/courses/{course}/communications`.

| Путь | Методы и назначение |
|---|---|
| `/audience` | POST — безопасный расчёт аудитории и доступных получателей |
| `/preview` | POST — серверный HTML с данными автора/безопасными примерами |
| `/test` | POST — поставить тест на собственный email в очередь |
| `/campaigns` | GET — items, общие stats; POST — создать черновик |
| `/campaigns/{id}` | GET, PUT с revision, DELETE только черновика |
| `/campaigns/{id}/duplicate` | POST — независимая копия черновиком |
| `/campaigns/{id}/launch` | POST — confirm + revision, транзакционная фиксация аудитории |
| `/campaigns/{id}/cancel` | POST — отменить ожидающие сообщения |
| `/templates` | GET встроенных/собственных, POST собственного шаблона |
| `/templates/{id}` | PUT/DELETE с revision |
| `/automations` | GET items/triggers, POST черновика |
| `/automations/{id}` | GET, PUT состояния/конфигурации с revision |
| `/automations/{id}/runs` | GET — события, условия и причины пропусков |
| `/automations/{id}/history` | GET — сообщения сценария |
| `/deliveries` | GET — история; фильтры campaign/automation |
| `/deliveries/{id}/retry` | POST — ручной повтор; confirm_uncertain при неизвестном результате |

Коллекции рассылок, сценариев, событий и отправок используют `before` и страницы по 100 записей. Сводка рассылок вычисляется по всем доступным рассылкам, независимо от текущей страницы. Список рассылок поддерживает `status`.

Настройки: GET/PUT `/api/academy/communication-preferences` только для текущего пользователя. GET/POST `/api/academy/unsubscribe/{token}` — подтверждение/отписка без раскрытия email.

## Очередь, время и гарантии

- Worker включён в прежний lifecycle context/WaitGroup, опрос очереди раз в 2 секунды; наблюдение событий раз в минуту. HTTP не отправляет массовую почту.
- Задачи, события, ключи дедупликации и сроки хранятся в PostgreSQL и переживают перезапуск. Несколько экземпляров приложения защищены транзакциями, advisory claim lock, row locks и уникальными ключами.
- Перед действием повторно проверяются пользователь, зачисление, срок доступа, права автора/куратора, сегмент, актуальность события, активность сценария и подписка фактического получателя. Изменение расписания отменяет устаревший источник. Принятое/отправленное задание исключает напоминание о его сдаче. Возобновление активности отменяет старое напоминание.
- Пауза удерживает ожидающие действия. Архив/новая конфигурация отменяют их. Новое поколение конфигурации начинает наблюдение с новой активации, не повторяя старые события. События, произошедшие во время простой паузы без изменения конфигурации, обрабатываются после возобновления.
- События: зачисление, подтверждённый запуск потока, открытие модуля/урока, открытие учеником урока, завершение урока/курса, результат теста, отправка/проверка/доработка задания, дедлайны, неактивность, назначение куратора. Старт потока означает подтверждённое автором действие запуска, как в Этапе D.
- Действия: сразу, через интервал, до дедлайна, в абсолютный момент. UTC timestamptz + IANA зона. UI отвергает несуществующее/неоднозначное местное время при DST. Условия проверяются повторно в момент действия. Абсолютное время действия ограничено снизу временем триггера; досрочная отправка возможна только явно заданным режимом до дедлайна.
- Лимиты: 30 email/минуту на систему, 3 email/час и 10/сутки на получателя; in-app 10/час и 30/сутки; реклама не чаще одного сообщения в сутки; тест — только собственный email, до 3 постановок в час. Транспортные повторные попытки тоже учитываются в лимитах.
- Определённые временные ошибки: до пяти автоматических попыток с экспоненциальной задержкой. Ручной повтор допускается до суммарных десяти попыток. Неопределённый SMTP-результат/протухший sending lease → failed + uncertain, без автоматического повтора. Ручной повтор требует отдельного подтверждения риска дубля.
- Стабильный Message-ID и уникальные ключи уменьшают дубли. **SMTP не обеспечивает exactly-once** при обрыве между приёмом письма и фиксацией результата в БД.
- `sent` означает принятие SMTP-сервером, а не доставку во входящие. `delivered` зарезервирован для будущего подтверждения провайдера. Открытия/клики/пиксели не реализованы и не выдаются за статистику.

## Production и ограничения

Используется прежняя SMTP-конфигурация из `mailer.go`, включая существующее TLS-соединение и MIME-формирование. Требуется корректный HTTPS `APP_BASE_URL`; SMTP-секреты не хранятся в сообщениях и технических логах. Нужны обычные настройки домена отправителя у почтового провайдера. Email рендерится для типовых клиентов; реальная проверка во всех Outlook/Gmail-клиентах требует тестовых ящиков и production-конфигурации, массовые реальные отправки при разработке не выполняются.

Категория «сопровождение» предназначена для обучения, рекламная категория требует согласия самого получателя. Отписка не обходится автоматизациями. Системные письма авторизации/безопасности не затрагиваются. Произвольные внешние списки email и глобальная база пользователей недоступны.

Не реализованы Telegram/WhatsApp, LLM, произвольные графы, tracking opens/clicks и выдуманные delivery webhooks. Будущий ИИ может вызывать только те же ограниченные API с действующими правами, согласием, аудитом и лимитами. Новые каналы/действия добавляются через структурированную конфигурацию и транспорт.
